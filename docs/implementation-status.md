A subsequent startup fix addresses `remote-companion: unsafe private directory`. Linux regressions reproduced an owned 0775 DSH_HOME and overly readable reused private directories. Companion now validates directory type, ownership, and descriptor inode before removing excessive permissions. Symlinks, foreign-owned directories, and world-writable directories remain rejected. This change modifies Companion source and rebuilds both the standalone archive and committed Git runtime.

Native permission regressions, real Git installation followed by runtime activation, identity routing, restricted helper queries, and descriptor disposal passed in isolated WSL Ubuntu with fixture services. Evidence is in `docs/evidence/permissions-*.txt`. User-provided terminal output confirms the screenshot machine has an owned 0775 `.dsh` and no private subtree, matching the failing regression. SSH to that machine was refused.

The user subsequently reported an installed runtime SHA-256 matching the repaired file, while the screenshot still referenced original runtime line numbers. After fully restarting the Harness process running the web profile, the user confirmed Agent enabled successfully. Installed-host activation is user-reported passed; the separate two-machine SSH/frp workflow remains notRun.

On 2026-10-15 a descriptor repair loop was added after a live Ubuntu host lost its launch descriptor while the Web process kept running. Companion had published the file only at activation and application readiness, so a profile live reload or a plugin-manager run deleted it without a replacement publication and every later connection attempt failed with the remote helper message until an operator restarted the service. Companion now publishes at activation, again on readiness, and every five seconds while the file is missing, replaced by another boot, incomplete, or bound to another port; disposal still removes only its own boot's descriptor. Windows and Ubuntu unit tests, the installed-runtime fixture that deletes the descriptor mid-run, a fresh build, and a live-host deletion check passed: the descriptor was deleted at 23:25:26.273, the helper answered `INFO_FAILED`, and the file was republished 3358 ms later with the same bootId, mode 0600 and a working helper query. Evidence is in `docs/evidence/repair-*.txt`. `scripts/install-remote-helper.mjs` was added so the controller's fixed `/usr/local/bin/dsh-remote-info` can be installed with one command and verified; without sudo it installs the owner-only `~/.local/bin` wrapper and prints the helperPath that the controller profile must override. A plugin-manager run that loads the live profile tree could not be reproduced because the installed CLI aborts inside the Harness plugin manager reconcile step; the removal and replacement cases are covered by the fixture and live deletion checks.
